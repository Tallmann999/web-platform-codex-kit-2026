## Модель
Это поставка игры в партнёрскую сеть, а не обещание трафика. Согласовать право дистрибуции, каналы/исключения, public game ID, hosting/upload mode, SDK и договор выплаты. Не отдавать пересекающийся канал второму дистрибьютору автоматически.

## SDK / реклама
Официальная инструкция задаёт `window.GD_OPTIONS`, `gameId`, `onEvent`, загрузку SDK один раз. `SDK_GAME_PAUSE` приостанавливает игру и звук; `SDK_GAME_START` возвращает управление после рекламы, а не обязательно обозначает начало новой сессии.
Для rewarded документируется `gdsdk.showAd('rewarded')`; подтверждение полного просмотра — событие `SDK_REWARDED_WATCH_COMPLETE`. Завершение Promise или закрытие не считать достаточными. В кабинете требуется включённая rewarded-возможность. Проверить текущую сигнатуру и настройки в preview перед production.
Показы по действию пользователя, вне активного gameplay; no-fill/error не блокируют игру. Инструкция pre-roll/mid-roll и ограничения кабинета проверяются вместе, без собственной агрессивной частоты.

## Не перепутать разработку SDK со сборкой игры
README репозитория содержит npm/grunt-команды для самого SDK. **Не внедрять Grunt и не собирать SDK из исходников ради пользовательской игры.** Использовать разрешённую CDN/интеграцию и существующий build pipeline игры.

## Данные/магазин/рейтинг
Store API отдельно документирован, но доступность, договор и применимость нужному порталу не подтверждены. Для первого билда рекомендовать ads-only. Не говорить «IAP технически не существует», но не подключать его без проверки.
Универсальный native leaderboard/save backend не подтверждён. Локальное сохранение и личный рекорд — допустимые проектные исходные варианты, если соответствуют правилам текущего договора. Общий backend — новый scope.

## QA
ZIP/внешний хост по кабинету, SDK ровно один, gameId правильный, запуск на партнёрском iframe, focus/mute/resume, no-fill, завершённый/прерванный rewarded, отсутствуют секреты. Проверить текущие требования к activation/test ads; не накручивать реальные показы. Подтвердить возможность выплаты конкретному контрагенту из России до платных затрат.
