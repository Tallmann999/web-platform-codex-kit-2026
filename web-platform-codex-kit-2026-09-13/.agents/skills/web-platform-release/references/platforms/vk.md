# VK — сначала определить продукт и runtime
Проверено: 2026-09-13. **ЧАСТИЧНО ПРОВЕРЕНО:** официальный GitHub доступен, ряд страниц dev.vk.com автоматически не открылся.

## Источники
- [Официальный VK Bridge](https://github.com/VKCOM/vk-bridge).
- [Портал разработчиков](https://dev.vk.com/) — требуется ручное чтение актуальных правил кабинета.
- [Обзор VK Mini Apps от VK](https://habr.com/ru/companies/vk/articles/961286/) — первичный обзор, не замена действующей модерации.
- [Публикация ОК через VK](https://dev.vk.com/ok/publishing) — официальный адрес из FAQ ОК, автоматическое чтение недоступно.
- [Гайд GamePush для VK](https://docs.gamepush.com/tutorials/adding-game-vk/) — вторичный к правилам хоста; маршрут перепроверить.

## STOP: не объединять разные системы
VK Mini Apps, старые embedded VK Games/Direct Games и VK Play — не одно и то же. Для игры, публикуемой через Mini Apps в разных хостах, требования и доступные методы проверять по конкретному хосту.
Сначала спросить/прочитать точный тип приложения, где оно запускается (web/mobile app/OK), разрешённые устройства, HTTPS-хостинг, app ID и способ SDK. Не подключать legacy AppsCentrum или старый order flow автоматически по стороннему tutorial.

## Что делать после подтверждения маршрута
Найти актуальные правила публикации/монетизации для этого типа. Проверить поддержку bridge-методов на runtime. Не принимать наличие названия метода в npm package за доступность рекламы/платежей данному приложению.
Для ads: init → availability → opt-in rewarded или разрешённый interstitial → pause/mute → подтверждение награды → безопасное восстановление. Точные методы/события записать только после официального чтения и preview-теста.
Для IAP: подтвердить доступ магазина, валюту, callbacks и необходимость server-side fulfillment. Секреты остаются на сервере/в кабинете. Не имитировать успешный платёж.
Для storage/auth: отдельно проверить scope, квоты, пользователя, подпись launch parameters при backend и поддержку гостя. Для leaderboard: подтвердить реальную услугу; иначе личный рекорд.

## Обязательные блокеры в SOURCE_REVIEW
Актуальные требования модерации; текущая рекламная схема; платежи для выбранного типа; допустимая сторона договора и выплаты; соответствие browser/mobile host. Пока неизвестно — UNKNOWN/BLOCKED для выпуска, а не «всё подключено».
Можно продолжить read-only аудит, MVP и адаптерный план без реальных секретов. Нельзя выпускать production SDK на основании предположений из старой статьи.

## QA
Нужен preview именно целевого VK/OK runtime, не только внешний URL. Проверить init, возврат из приложения/рекламы, resize и in-app browser, сохранение при смене аккаунта, отказ/ошибки рекламы, тестовые покупки при наличии доступа. Перепроверить договор и feature access в кабинете владельца.
