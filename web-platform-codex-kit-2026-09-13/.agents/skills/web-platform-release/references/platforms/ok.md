## Самое важное
Официальный FAQ сейчас предлагает **новые приложения публиковать инструментами VK Mini Apps**. Поэтому запрещено начинать новый проект с допущения «в ОК обязательно старый FAPI».
Первый вопрос: это новый Mini Apps проект с показом в ОК или существующая legacy FAPI-игра? Тип, кабинет и выданные требования записать в PLATFORM_PROFILE. Для нового маршрута совместно читать `vk.md`; не считать публикацию во VK автоматическим попаданием в каталог ОК.

## Legacy — только если этот маршрут подтверждён
В legacy docs описаны rewarded `FAPI.UI.loadAd` / `showLoadedAd` и interstitial `FAPI.UI.showAd`. Использовать их лишь для соответствующего runtime и по текущим callbacks. Наличие страницы не доказывает приём новых игр этим способом.
Документация рекламы предупреждает: оплачиваемые показы учитываются после заключения договора, не задним числом. Тестовую рекламу/покупки прогонять в официальном test mode. Не привязывать тесты к реальным списаниям.
IAP требует подтверждённого server/callback процесса по маршруту; не выдавать товар по клиентскому закрытию окна. Нельзя считать leaderboard встроенным, пока он не найден в актуальном API.

## Сохранения и интерфейс
Это проектные рекомендации: комфортный крупный UI, понятное сохранение, короткая сессия плюс долгосрочная коллекция. Возраст и платежеспособность не угадывать по названию соцсети.
Backend или интегратор для облака/рейтинга подключается только с согласованием стоимости и данных. Один SDK-владелец; не смешивать FAPI и VKBridge для одних lifecycle/ads без документированной необходимости.

## Профиль/QA/блокеры
Тип приложения, VK/OK host, ID, хостинг, SDK, рекламный договор, поддерживаемые устройства, save scope и платежный доступ. Проверить реальные web/mobile оболочки, ad success/close/error, foreground/background, сохранение и доступные test-mode платежи.
До прочтения актуальной инструкции нового маршрута и подтверждения кабинета статус выпуска BLOCKED. Не делать категорического вывода о разрешённых формах контрагента по устаревшему стороннему гайду.
