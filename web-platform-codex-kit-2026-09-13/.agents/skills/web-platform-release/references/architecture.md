# Малый адаптер вместо переписывания игры

Это рекомендуемая граница ответственности, не приказ создать новый фреймворк.

Игра → существующий сервисный слой или небольшой адаптер → один SDK-провайдер → площадка.
Для простого HTML-проекта достаточно одного модуля и конфигурации. Для Unity использовать существующий bridge/plugin и тонкую C#-границу. Не внедрять DI-контейнер, ECS, Redux, новый event bus или собственный backend ради одного SDK.

## Возможности, а не догадки
Зафиксировать значения supported / unsupported / gated / unknown отдельно для ads, rewarded, IAP, cloud, auth, leaderboard.
При запуске уточнять capability через доступное API провайдера. Реальное отсутствие функции не превращать в тестовый успех. Интерфейс пользователя должен скрывать недоступные действия или честно объяснять режим.

## Один владелец функции
Не загружать YaGames + прямые ads SDK поверх GamePush/Bridge, если это уже выполняет провайдер. Исключение возможно только по официальной инструкции, с однозначным владельцем lifecycle и отдельным согласованием. Не считать feature list SDK разрешением кабинета.

## Конфигурация сборок
Логический target задаётся при сборке/выборе официального профиля; runtime host определяется документированным SDK, если этого требует multi-host bridge. Не внедрять собственный domain-lock и недокументированное угадывание по URL.
Например: web-local, web-yandex, web-crazygames-basic, web-crazygames-full, web-poki, web-vk-miniapps, web-ok-via-vk, web-ok-legacy, web-gamedistribution, web-playgama.
Это названия профилей-примеры, не уже созданные команды npm.

Конфиги могут содержать public App ID и product ID. Нельзя включать secret API key, подпись магазина, секрет callback или личные токены. Префикс VITE_ не скрывает секрет: клиентский bundle публичен.

## Pause coordinator
Независимые причины паузы: user, focus, host, ad. Каждая закрывается только владельцем причины. Остановка игры включает таймеры экономики/боёв там, где это нужно по дизайну, input и звук.
При рекламе не ставить безусловно Time.timeScale=1 или unmute=true. Нужны прежняя скорость и выбор mute игрока. Не менять центральный менеджер без отдельного scope.

## Сохранения
Разные платформы могут иметь разных пользователей и изолированное хранилище. Единая кодовая база не даёт общего аккаунта. Согласовать schemaVersion, ревизию, временные метки, гостевое состояние и правило конфликтов. Не использовать только максимальное число монет: валюта могла законно уменьшиться после покупки.
При смене пользователя не смешивать его save с предыдущим. Проект с cloud/IAP не переводить на localStorage без миграционного плана.
