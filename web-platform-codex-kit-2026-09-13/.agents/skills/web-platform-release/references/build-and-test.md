# Раздельные сборки и проверка

## До запуска команд
Прочитать package.json и lockfile или Unity ProjectVersion/Packages/существующий editor build script. Команду не изобретать. npm install/ci запускает скрипты и меняет файлы/кеш; Unity может изменить проект — нужен согласованный scope.
Не обновлять движок и SDK одновременно. Сначала зафиксировать существующий воспроизводимый build.

## Профиль
Каждая согласованная цель получает output отдельно, например `builds/yandex/<version>/`. При наличии своей схемы каталогов сохранить её. Отдельно указывать artifact path и hosting mode: zip или внешний HTTPS.
В ZIP кладётся содержимое web-output, а не родительская папка/исходный репозиторий. index.html в корне — когда это требует портал. Приватные ключи, .git, .env, .agents, docs, node_modules, Unity Library/Temp отсутствуют.
Скрипт check_web_build принимает **распакованную папку**, не ZIP. Его лимиты задаёт пользователь по актуальному профилю. Общий статический размер не равен initial network download и не равен размеру сжатого ZIP.

## Общие технические проверки
Относительные пути/регистр, ассеты без 404, отсутствие случайных CDN и внешних запросов, iframe и resize, touch/drag без скролла страницы, mute, focus, полноэкранный режим по жесту пользователя, читаемость UI, ошибки консоли, CSP/CORS, разрешённые SDK-домены.
Для Unity отдельно: формат сжатия и Content-Encoding, MIME wasm, размер data/wasm и начальной загрузки, память, фризы/GC, поддержка конкретного устройства хостом. Не включать multithreading и cross-origin isolation автоматически.
Работа на ПК не доказывает работу в Android WebView/iOS. Не заявлять поддержку этих платформ без прогона.

## Ручная матрица
Десктоп и реальные целевые телефоны; Chrome/Edge и Safari по заявленным устройствам; узкий/широкий iframe; ориентация; fullscreen; язык ru/en; длинные строки; запуск инкогнито; хранилище недоступно; reload; reconnect; фон вкладки.
Реклама: success/skip/no-fill/error/duplicate/double click и focus во время ad. Покупки: cancel/paid/reload/duplicate/consume retry. Leaderboard: guest/auth/missing board/timeout/invalid score. Проверить и старую целевую сборку после общих изменений.

## Готовность
PASS только с доказательством: команда + exit code, браузер/устройство, среда localhost/preview/production, наблюдение. FAIL требует исправления; BLOCKED — внешние данные/доступ; NOT_RUN — не запускалось; N/A — функция отключена и это обосновано.
Автоматический поиск SDK в тексте не доказывает его работу; зашифрованные/сжатые файлы могут скрывать и ошибки, и секреты. Нет подтверждения интеграции в кабинете — не утверждать portal-ready.
