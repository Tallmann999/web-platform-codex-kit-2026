# Движки: не менять технологию при подключении портала

## Phaser / HTML5
Определи точную версию по package.json и lockfile, включая предварительные релизы. Phaser 4 существует как отдельная линия; не понижать её автоматически до 3 и не предполагать полной идентичности API.
Официальные страницы: https://phaser.io/download/phaser4 и https://docs.phaser.io/ . Для проекта выбирать документацию его версии.
Здесь предпочтительны 2D sorting, merge, idle и обслуживание заказов без тяжёлой физики. Это рекомендация по масштабу, не требование порталов.
Подстройка размеров экрана должна учитывать UI и координаты input; растяжение canvas не решает обрезку элементов. SDK и lifecycle подключать к существующим точкам запуска/паузы.
У обычного HTML без package.json может не быть шага компиляции: не создавать Vite/React только ради публикации. При наличии bundler использовать его текущую схему.

## Unity Web
Прочитать ProjectSettings/ProjectVersion.txt, Packages/manifest.json и существующий Web template/build script. Официальная точка документации: https://docs.unity3d.com/Manual/web.html ; выбрать установленную версию, а не самый новый редактор.
SDK-плагин или JS bridge согласовать отдельно. Не клонировать GameManager, не удалять Packages, не менять render pipeline, scripting backend, сцены и ProjectSettings вне разрешённых файлов. Подключение портала не повод переносить игру на Phaser.
Для маленьких 2D игр оценить фактическую загрузку/память. Рабочая Unity-игра может быть лучшим основанием, чем переписывание с нуля; перенос движка — отдельная бизнес-задача.

## Команды
Ни `npm run build`, ни `Unity -batchmode ...` не считаются существующими автоматически. Сначала найти script/метод/путь и права на создание output. Скрипты сборки SDK в стороннем репозитории не являются командами сборки игры.
